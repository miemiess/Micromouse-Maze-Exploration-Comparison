# 算法登记与方法小节（B1）

本文登记项目已实现的全部算法，供报告“方法”一节使用。按 README 要求，每个算法在运行实验前登记：信息假设、方向选择规则、失败与终止条件、是否含随机性、复杂度，并注明来源。所有实现均为本组按 `src/algorithm_api.py` 接口自行编写，**没有复制第三方代码**。文献出处在完成核查前标注“待核查”，报告中不宣称首创。

## 1. 共同模型与口径

- **网格与墙**：W×H 网格，左下角为 (0, 0)；墙位于相邻两格之间的边上，外边界始终为墙（见 `src/README.md`）。
- **两类算法**（`src/algorithm_api.py`）：
  - **未知地图探索**（`EXPLORE`）：每到一格只获得该格四个方向是否有墙（理想观测），通过 `choose_direction` 逐步决定方向；
  - **已知地图规划**（`KNOWN_MAP`）：通过 `plan(maze)` 一次拿到完整地图，返回整条路径，作为参照。两类分开实验、分开比较。
- **代价**：一次跨格移动算 1 步；转向单独计数，180° 记为两次 90°。基础规则下每一步代价相同。
- **终止状态**：`success`（到达任一目标）、`no_path`（算法返回 None）、`loop_detected`（算法返回 None 且判定陷入循环，目前只有沿墙法）、`budget_exceeded`（默认 20 × 格子数步）、`timeout`（累计计算超过 30 秒）、`invalid_action`、`error`。
- **统一驱动**：所有算法都由 `Runner` / `run_episode` 驱动 `MazeEnvironment` 执行，只对算法自身的 `reset` / `plan` / `choose_direction` 计时，统计口径完全一致。

## 2. 算法登记表

| 算法（文件） | 类别 | 信息假设 | 方向选择规则 | 失败 / 终止 | 随机性 |
| --- | --- | --- | --- | --- | --- |
| 随机游走（`random_walk.py`） | 探索 | 只用当前观测，不记忆 | 在无墙方向中等概率随机选（可掉头） | 通常耗尽移动预算 | 有：`random.Random(seed)`，seed 为 None 时用 0 |
| 左手 / 右手沿墙法（`wall_follower.py`） | 探索 | 只用当前观测和自身朝向 | 贴墙一侧 → 直行 → 另一侧 → 掉头 | 同一（位置, 朝向）重复出现即判定循环，返回 None | 无 |
| DFS＋实际回溯（`dfs.py`） | 探索 | 观测＋自身访问记录 | 按 N/E/S/W 选第一个无墙且未访问的邻格；无则沿原路真实回溯 | 栈空（可达格全部访问）返回 None | 无 |
| 贪心 DFS（`greedy_dfs.py`） | 探索 | 同 DFS，另用目标坐标 | 同 DFS，但候选按“到最近目标的曼哈顿距离”排序，平局优先直行、再 N/E/S/W | 同 DFS | 无 |
| Flood-Fill（`flood_fill.py`） | 探索 | 观测＋在线墙地图；未知边视为可通行 | 每步从目标做 BFS 全量重算距离，走向距离最小的邻格；平局优先未访问、直行、N/E/S/W | 当前格在已知墙下不可达任何目标时返回 None | 无 |
| 重复 A*（`repeated_astar.py`） | 探索 | 同 Flood-Fill（乐观假设） | 从当前位置用 A*（曼哈顿启发式）规划到目标并沿计划走；计划被新墙挡住时才重新规划 | 乐观地图上也无路时返回 None | 无 |
| BFS（`bfs.py`） | 已知地图 | 完整地图 | 从起点 BFS，按 N/E/S/W 扩展，首次取出目标即得最短路 | 目标不可达返回 None | 无 |
| A*（`astar.py`） | 已知地图 | 完整地图 | f = g + h，h 为到最近目标的曼哈顿距离；平局优先 h 小、再按入队顺序 | 目标不可达返回 None | 无 |

## 3. 复杂度

记 V 为格子数（16×16 时 V = 256），E 为相邻且无墙的边数（E ≤ 2V）。“每步决策”指一次 `choose_direction` 的计算量，“移动”指实际跨格步数，两者分开报告。

| 算法 | 每步决策 / 规划 | 移动步数上界 | 内存 |
| --- | --- | --- | --- |
| 随机游走 | O(1) | 无上界（由预算截断） | O(1)（显示用计数另计） |
| 沿墙法 | O(1) | ≤ 4V 次决策后到达或判定循环 | O(V)（循环检测） |
| DFS / 贪心 DFS | O(1) | ≤ 2 ×（可达格子数） | O(V) |
| Flood-Fill | 每步 O(V + E) 全量 BFS | 理论上界需另行分析；实验中统计 | O(V) |
| 重复 A* | 仅在需要时规划，每次最坏 O(V log V)；其余步 O(计划长度) | 同上 | O(V) |
| BFS（已知地图） | 一次 O(V + E) | 等于最短路长度 | O(V) |
| A*（已知地图） | 一次最坏 O(V log V) | 等于最短路长度 | O(V) |

注意：探索算法的总计算量 = 每步决策成本 × 决策次数，不能把静态 BFS 的一次遍历复杂度直接当作整段在线探索的总成本。

## 4. 设计上的对照关系

每个算法都至少有一个可以对照的对象，比较时控制其余条件不变：

| 对照 | 只改变了什么 | 要回答的问题 |
| --- | --- | --- |
| 随机游走 → 其他所有算法 | 有无任何策略 | 下界：策略带来多少提升 |
| DFS → 贪心 DFS | 只改邻格排序（消融） | 目标方向启发式在迷宫中是帮助还是误导 |
| Flood-Fill ↔ 重复 A* | 乐观假设相同，计算方式不同（全量反向传播 vs 按需正向搜索） | 路线是否相近，计算量差多少 |
| 沿墙法 → DFS | 是否记忆访问 | 不记忆地图的局部策略在中心目标下为何失败 |
| BFS ↔ A* | 是否使用启发式 | 基础规则下最短路长度必然相同，只比较扩展节点数 |
| 探索算法 ↔ BFS 最短路 | 是否知道完整地图 | “探索步数 ÷ 最短路长度”：比全知最优多走多少 |

基础规则下 Dijkstra 与 BFS 完全等价（所有边代价为 1），因此不单独实现；只有引入转弯代价（见 README“扩展规划”）后 Dijkstra 才有独立意义。

## 5. 第三方源码阅读记录

README 列出的候选源码中，与本组实现直接相关的两份已阅读，记录如下（阅读日期 2026-11-18）：

**① Python Flood-Fill**（[ParameswaranSajeenthiran/FloodFill-Maze-Solver-Algorithm](https://github.com/ParameswaranSajeenthiran/FloodFill-Maze-Solver-Algorithm)，`Main.py`，提交 `5f9a614`，MIT 许可证）

- 基于 MMS 模拟器的 Python 模板，通过前、左、右三个相对方向的传感器读墙，地图尺寸与中央目标写死为 16×16。
- 距离初值为到中央的曼哈顿距离；发现新墙后用栈做“一致性修复”，只更新距离值不一致的格子，属于**增量式（modified）Flood-Fill**。本组的 `flood_fill.py` 每步全量重算，二者路线规则相近、计算量不同，增量版可作为后续“增量重算”任务的参考。
- 每个格子的墙用 0～14 的编码只记录在当前格，判断能否通行时也只看出发格的编码，**相邻格之间没有双向同步墙**；本组按 `src/README.md` 要求双向同步。
- 平局按 N/E/S/W 中第一个最小值选择，不考虑直行；主循环没有到达目标后的终止，返回起点的代码被注释掉。
- 结论：只作为思路参考，未复制代码；本组实现支持任意尺寸与目标、双向同步墙、明确的平局与终止规则。

**② PythonRobotics A\***（[AtsushiSakai/PythonRobotics](https://github.com/AtsushiSakai/PythonRobotics)，`PathPlanning/AStar/a_star.py`，最近修改提交 `2916273`；GitHub 未能自动识别许可证，引用前需核对仓库 LICENSE 文件）

- 已知地图上的 A*，**8 方向移动**（对角线代价 √2），启发式为欧氏距离，障碍物以点加机器人半径表示。
- 本组迷宫为 4 方向移动、墙在格子边上，因此改用曼哈顿距离启发式（4 方向、单位代价下可采纳且一致），未复制代码。
