# 未知迷宫中电脑鼠探索算法的比较与分析：问题建模与算法选择

> **文档状态**：中文初稿（2026-11-19），定稿后译为英文提交。
> 第 2 章的数据来自初步实验（`results/preliminary/`），用于说明算法选择的理由；正式结论以 D2 批量实验为准。
> 第 3、4 章中标注“待实现”或“待验证”的内容尚无实验支持，只是设计与假设。

## 摘要

本项目研究一个经典的 AI 问题：**一辆小车（电脑鼠）在事先不知道地图的迷宫中，只能边走边看，如何尽快到达目标？**
我们按计算思维的步骤推进：先把现实问题**抽象**成“未知图上的在线寻路”，再**分解**为“记录已知信息、选择下一步、判断何时停止”三个子问题，通过**模式识别**把它与图遍历、最短路等已知问题联系起来，然后**设计**并实现了 7 个探索算法和 2 个已知地图参照算法。
在 33 张迷宫上的初步实验表明：**没有一个算法在所有迷宫上都最好**，迷宫结构（有无环路）决定了算法的优劣；在“一步代价为 1、观测准确”的基础环境中，基于乐观假设的 Flood-Fill 与重复 A* 最稳定，而重复 A* 用约 1/11～1/19 的计算量达到了与 Flood-Fill 相近的步数。
最后，我们讨论如何放宽假设、靠近现实，引入启发式与近似算法，并提出一个新方案：**代价感知的乐观重规划，加上有误差界的提前停止**。

## 1. 现实问题与计算思维建模

### 1.1 现实问题

很多真实系统都要在**信息不完整的环境中做决策**：

- 扫地机器人第一次进入一个新房子，不知道户型；
- 仓库机器人或无人机遇到货架挪动、通道被堵，需要改道；
- 搜救机器人在结构未知的废墟中寻找被困者；
- 电脑鼠比赛：小车被放进一个从未见过的 16×16 迷宫，要尽快找到中央的目标区。

它们的共同点是：**地图只能边走边了解，而每一步移动都有代价**。走得越多，耗电越多、时间越长；算得越久，反应越慢。本项目以电脑鼠为原型研究这一类问题。

### 1.2 从最简单的情形开始：抽象

计算思维的第一步是抽象：保留与“决策”相关的本质，去掉其他细节。我们先考虑**最简单的情形**：一个简单的迷宫，一辆不分层（不单独考虑传感器和电机）、每走一格代价都为 1 的小车。

| 现实世界 | 抽象后的模型 | 有意忽略的细节 |
| --- | --- | --- |
| 迷宫场地 | W×H 的网格；格子是图的**节点** | 尺寸、材质 |
| 通道与墙 | 相邻两格之间没有墙就连一条**边**；墙 = 删掉这条边 | 墙的厚度、安装误差 |
| 红外传感器 | **理想观测**：到达一格后，准确知道它四个方向有没有墙 | 噪声、误判、视野限制 |
| 电机运动 | **走一格 = 1 步**；转向单独计数，不影响代价 | 加减速、打滑、转弯耗时 |
| 小车的位置 | 准确知道自己在哪一格、朝哪个方向 | 定位误差 |

这些抽象是**有意的设计选择**：只保留决策层，就能保证实验中观察到的差异只来自算法本身，而不是传感器噪声或电机误差（相当于控制变量）。第 3 章再逐步把被忽略的因素加回来。

### 1.3 问题形式化

把迷宫看成一个无向图 G = (V, E)，|V| = W × H。

| 要素 | 定义 |
| --- | --- |
| 输入 | 网格尺寸 W、H，起点 s，起始朝向，目标集合 T（16×16 时为中央 2×2）。**边集 E 一开始未知** |
| 观测 | 小车到达格子 v 后，得知 v 的四条边中哪些存在 |
| 动作 | 每一步移动到一个相邻且无墙的格子（北、东、南、西四个方向之一） |
| 目标 | 到达 T 中任意一格，并使移动步数尽量少 |
| 次要指标 | 转向次数、重复访问次数、算法计算时间 |
| 终止 | 到达目标；或算法声明无路；或超出移动预算（20 × 格子数）；或计算超时（30 秒） |

这是一个**在线问题**：算法每一步都必须在只知道部分地图的情况下做决定，不能先看完整地图再规划。与之对应的**离线问题**（一开始就知道 E）就是普通的图最短路问题，可以用 BFS 精确求解。离线最优解是衡量在线算法的参照：

> **竞争比（本文称“步数 / 最短路”）** = 在线算法的实际步数 ÷ 已知地图下的最短路长度，越接近 1 越好。

### 1.4 分解：把问题拆开

任何探索算法都要回答三个子问题：

1. **记住什么？**（知识表示）：什么都不记 / 记住去过哪里 / 记住看到的每一面墙；
2. **下一步去哪？**（决策规则）：局部规则 / 系统地遍历 / 先假设地图再规划；
3. **什么时候停？**（终止条件）：到达目标、确认无路、发现陷入循环。

项目实现也按同样的方式分解，各部分独立、可替换：

| 模块 | 职责 | 文件 |
| --- | --- | --- |
| 环境 | 持有真实地图，提供观测，执行移动，统计步数与转向 | `src/environment.py` |
| 算法 | **只**回答“下一步往哪走”，看不到真实地图 | `src/dfs.py` 等，每个算法一个文件 |
| 统一接口与驱动 | 发现算法、按统一规则运行和计时 | `src/algorithm_api.py` |
| 可视化与实验 | 上位机演示、批量实验 | `tools/MazesTest/`、`results/` |

### 1.5 模式识别：与已知问题建立联系

- **已知地图时**：在单位代价的图上找最短路，就是 **BFS**；加上启发式就是 **A***。
- **完全不记忆时**：只能靠局部规则，例如沿墙走，这是一个**有限状态机**。
- **记住访问过的格子时**：系统地走遍所有可达格子，就是**图的深度优先遍历（DFS）**，只是回溯必须真实地走回去。
- **记住墙并做假设时**：把未知的边**乐观地**当作通路，问题又变回已知地图上的最短路。每发现一面新墙，就修正地图、重新规划。**Flood-Fill 本质上就是从目标出发的 BFS**，所以不能把“BFS”和“Flood-Fill”当成两种无关的方案。

由此得到三类策略，对应“记住什么”的三种选择：

| 策略族 | 记忆 | 代表算法 |
| --- | --- | --- |
| 局部规则 | 不记地图 | 随机游走、沿墙法 |
| 系统遍历 | 记住访问过的格子 | DFS、贪心 DFS |
| 乐观规划 | 记住所有看到的墙，并假设未知边可通行 | Flood-Fill、重复 A* |

### 1.6 好算法应该满足什么

在设计具体算法之前，先明确要求：

1. **不偷看**：探索算法只能使用观测，不能读取真实地图。这一点由接口强制保证。
2. **必定终止**：在有限迷宫中，要么到达目标，要么在有限步内声明无路，不能无限循环。
3. **规则无歧义**：平局时选哪个方向必须写清楚，保证结果可以复现。
4. **可度量**：步数、转向、计算时间分开统计，**移动成本和计算成本不能混为一谈**。

## 2. 候选算法与当前环境下的对比

### 2.1 候选算法与选择理由

每个算法都有一个**纳入比较的理由**，而不是越多越好。完整的登记（信息假设、平局规则、失败条件、复杂度）见 [`Docs/algorithm-methods.md`](algorithm-methods.md)。

| 算法 | 类别 | 核心规则 | 为什么纳入 |
| --- | --- | --- | --- |
| 随机游走 | 局部规则 | 在无墙方向中随机选 | **下界**：衡量“有策略”比“没策略”好多少 |
| 沿墙法（左 / 右手） | 局部规则 | 始终贴着一侧墙走；（位置, 朝向）重复即判定循环 | 最简单、几乎零计算；检验“不记忆地图”的极限 |
| DFS＋实际回溯 | 系统遍历 | 按北东南西选未访问邻格，走不通就原路退回 | 保证走遍所有可达格子（完备），不依赖任何假设 |
| 贪心 DFS | 系统遍历 | 同 DFS，只是优先选离目标近的邻格 | **消融对照**：只改一个排序规则，看目标方向的启发式有多大作用 |
| Flood-Fill | 乐观规划 | 未知边视为通路，每步从目标做 BFS 全量重算距离，走向距离最小的邻格 | 电脑鼠比赛的经典方法 |
| 重复 A* | 乐观规划 | 与 Flood-Fill 假设相同，但只在计划被新墙挡住时才从当前位置用 A* 重新规划 | 与 Flood-Fill 比较“同样的假设、不同的计算方式” |
| BFS（已知地图） | 参照 | 一开始就知道完整地图 | 给出最短路，用来计算“步数 / 最短路” |
| A*（已知地图） | 参照 | 曼哈顿距离启发式 | 与 BFS 比较启发式能少搜多少格子 |

两点说明：

- **为什么没有单独实现 Dijkstra**：在每步代价为 1 的图上，Dijkstra 与 BFS 完全等价。它只有在引入转弯代价（第 3 章）后才有独立意义。
- **已知地图算法不参与排名**：它们看得到完整地图，只作为参照，与探索算法分开比较。

### 2.2 复杂度

V 为格子数（16×16 时为 256），E 为无墙的相邻边数（E ≤ 2V）。

| 算法 | 每一步的计算量 | 移动步数 | 额外内存 |
| --- | --- | --- | --- |
| 随机游走 | O(1) | 无上界，由预算截断 | O(1) |
| 沿墙法 | O(1) | 最多 4V 次决策就会到达目标或判定循环 | O(V) |
| DFS / 贪心 DFS | O(1) | ≤ 2 × 可达格子数 | O(V) |
| Flood-Fill | O(V + E)（**每一步**都全量重算） | 实验统计 | O(V) |
| 重复 A* | 只在被挡住时规划，单次最坏 O(V log V)；其余步只检查计划 | 实验统计 | O(V) |
| BFS / A*（已知地图） | 只规划一次：O(V + E) / O(V log V) | 等于最短路长度 | O(V) |

两个需要说明的地方：

- **沿墙法为什么一定会停**：它的下一步只取决于（位置, 朝向），一共只有 4V 种状态。按抽屉原理，最多 4V 步后状态必然重复；而状态一旦重复，之后的路线就会无限循环。所以只要检测到状态重复就可以停止，这同时证明了它必定终止。
- **单步复杂度 ≠ 总复杂度**：探索算法的总计算量是“每步计算量 × 决策次数”，不能把一次 BFS 的复杂度当作整段探索的成本。

### 2.5 分析

**发现 1：迷宫结构决定算法的优劣，没有“永远最好”的算法。**
沿墙法在无环迷宫上 10/10 成功，环路比例升到 30% 时降为 0/10。原因可以从理论上解释：在没有环路的迷宫中，所有墙都与外墙连成一片，贴着墙走一定能走遍整个迷宫；一旦出现环路，目标就可能落在一座“孤岛”上，沿墙法只会绕着外圈打转。比赛迷宫的中央目标正是这样设计的，所以 3 张比赛迷宫中只有 1 张能用沿墙法走到。

**发现 2：乐观规划在所有地图组都最稳定。**
Flood-Fill 和重复 A* 在全部 33 张地图上都成功，各地图组的平均“步数 / 最短路”在 1.00～1.70 之间，是探索算法中最好的。原因是它们**记住了所有看到的墙**，并且始终朝着“在已知信息下看起来最短”的方向走，被新墙挡住后立即修正。

**发现 3：同样的步数，计算量可以差一个数量级。**
重复 A* 与 Flood-Fill 的步数几乎相同，但计算时间只有后者的 1/11～1/19。两者对未知边的假设完全相同，差别只在计算方式：Flood-Fill **每一步**都把所有格子的距离重算一遍，重复 A* 只在计划被挡住时才重新搜索，而且搜索范围受启发式引导。这说明评价算法时**必须把移动成本和计算成本分开**；只看步数，会以为两者没有区别。

**发现 4：不利用目标信息的 DFS 在环路多时会严重退化。**
DFS 的“步数 / 最短路”从无环迷宫的 1.19 恶化到 30% 环路时的 10.26：环路越多，最短路越短，但 DFS 按固定方向顺序遍历，经常先钻进远离目标的区域。贪心 DFS 只改了一个排序规则，就把这个比值降到 1.62。这个消融对照说明，**目标方向的启发式在开阔迷宫中价值很大**。不过在比赛迷宫上它也只降到 2.38，因为墙会让“离目标近”的方向变成死路。

**发现 5：启发式的效果取决于地图结构。**
A* 与 BFS 找到的最短路长度完全相同（单位代价下必然如此），只有扩展的节点数不同。在比赛迷宫和无环迷宫上，A* 只少扩展 6%～7%；在环路多的迷宫上能少 49%～64%。原因是走廊曲折时，曼哈顿距离严重低估真实距离，启发式几乎提供不了方向信息；迷宫越开阔，曼哈顿距离越接近真实距离。

**发现 6（已核实为生成器偏差）：在递归回溯生成的无环迷宫上，乐观规划 10/10 恰好走出最短路，但换一种生成器后不再成立。**
我们先排除了程序错误：这些地图的最短路上有多个岔路口（例如种子 1 的最短路上有 9 个），Flood-Fill 每次都选对了方向。随后我们实现了另外三种经典生成算法，在同样尺寸、同样种子 1～10 的无环迷宫上重测：

| 生成器 | 死胡同数（种子 1） | Flood-Fill 平均“步数 / 最短路” | 恰好最优 | 重复 A* | DFS |
| --- | --- | --- | --- | --- | --- |
| 递归回溯 | 28 | 1.00 | 10/10 | 1.00 | 1.19 |
| Wilson（均匀随机生成树，无偏） | 78 | 4.62 | 1/10 | 2.93 | 6.06 |
| 随机 Prim | 80 | 5.18 | 0/10 | 5.75 | 11.87 |
| 随机 Kruskal | 74 | 1.57 | 1/10 | 1.70 | 10.28 |

递归回溯生成的迷宫走廊长、死胡同少，只有前三分之一左右；乐观规划在这种结构上几乎不会被误导。换成无偏的 Wilson 生成器后，Flood-Fill 平均要走最短路的 4.6 倍。因此，表 1、表 2 中“无环迷宫”一列只代表递归回溯这一种结构，**不能推广到一般的无环迷宫**；发现 5 中“无环迷宫上 A* 只少扩展 6%～7%”同样受此影响。这说明**只用一种生成器得到的结论可能完全不成立**，正式实验必须使用多种生成器和真实比赛迷宫。（数据为本节补充的初步测量，正式实验需重新运行。）

**随机游走**作为下界，在比赛迷宫上全部耗尽预算；在开阔的迷宫上虽然能走到，但步数约为最短路的 28～32 倍。注意它的平均值只统计了成功的运行，存在幸存者偏差。

### 2.6 当前环境下的算法选择结论

在“每步代价为 1、观测准确”的基础环境中：

| 场景 | 推荐 | 理由 |
| --- | --- | --- |
| 一般的未知迷宫 | **重复 A***（或 Flood-Fill） | 步数最少且最稳定；重复 A* 的计算量小一个数量级，更适合计算资源有限的小车 |
| 已知迷宫没有环路 | 沿墙法 | 几乎不需要计算和内存，且在这种迷宫上必定能走到 |
| 只要求一定走遍、不在乎步数 | DFS | 不依赖任何假设，保证访问所有可达格子 |
| 需要一个参照标准 | BFS（已知地图） | 给出最短路，用于计算“步数 / 最短路” |

需要强调的是，这个结论依赖于基础环境的假设。代价规则一变（例如转弯很贵），最优选择就可能改变，这正是第 3 章要讨论的。

### 2.7 有效性威胁

- **样本量小**：只有 3 张比赛迷宫和 30 张生成迷宫，正式实验需要按计划扩充到至少 20 张有代表性的测试地图，并分开开发集和测试集。
- **生成器单一**：表 1、表 2 只用了递归回溯一种生成方法，发现 6 已证实它会使结论明显偏向乐观规划。上位机已加入 Wilson、Prim、Kruskal 生成器，并从 micromouse_maze_tool 导入了更多比赛迷宫，正式实验应覆盖这些来源。
- **理想化假设**：观测准确、单位代价，这些假设对结论的影响要在第 3 章的扩展实验中检验。
- **计时依赖机器**：计算时间受 Python 版本和机器影响，只能用于同一台机器上的相对比较，并且需要重复测量。

## 3. 走向现实：放宽假设，引入启发式与近似算法

### 3.1 模型与现实的差距

| 第 1 章的假设 | 现实情况 | 放宽后带来的新问题 |
| --- | --- | --- |
| 每一步代价相同 | 转弯要减速，直线可以加速 | “最短”不再等于“最快”，需要按时间或加权代价规划 |
| 观测准确 | 红外传感器会误报和漏报 | 墙的存在变成概率，需要融合多次观测 |
| 计算不受限 | 小车上的单片机算力有限，要实时决策 | 精确算法可能来不及算完 |
| 只要到达目标 | 比赛规则是先探索、再冲刺 | 要决定**探索到什么程度就可以停** |
| 迷宫只有 16×16 | 仓库、楼宇的地图大得多 | 每步全量重算的成本迅速增长 |

当问题变得更真实，**精确最优**往往要么算不起，要么没法定义。这时就需要两类工具：

- **启发式算法**：用经验规则引导搜索，通常更快，但**不保证**结果的质量；
- **近似算法**：用一部分最优性换取效率，但能**证明**结果与最优解的差距不超过某个界限。

### 3.2 启发式

项目中已经用到了两种启发式，它们的效果都可以直接测量：

- **A* 的曼哈顿距离启发式**：不会高估真实距离（可采纳），所以 A* 仍能保证找到最短路。发现 5 表明它的效果取决于地图结构。
- **贪心 DFS 的邻格排序**：优先选离目标近的方向，不保证最优，但在开阔迷宫上大幅减少了步数（发现 4）。

引入转弯代价后，启发式也要跟着设计。例如，当前位置与每个目标格都既不同行也不同列时，路线必须同时包含横向和纵向的移动，至少要转一次弯，于是可以用“曼哈顿距离 + λ × [至少需要的转弯次数]”作为启发函数。它仍然不会高估真实代价，所以 A* 的最优性得以保留。

另一类启发式是**加权评分**：把目标距离、预计转弯、重复访问、能获得的新信息等因素加权求和，用来给候选方向打分。这些权重无法用梯度方法求解，因为“权重 → 平均步数”的关系呈台阶状、不可微，而且有很多局部最优；适合用**元启发式**（随机搜索、模拟退火）在开发地图上调参，冻结后再到测试地图上评估。（待实现）

### 3.3 近似算法

**① 加权 A*（有界次优）**：把 A* 的估价函数改为 f = g + w·h（w ≥ 1）。经典结论是：找到的路径代价**不超过最优解的 w 倍**，而扩展的节点通常少得多。这就把“要多精确”变成了一个可以调节的参数，适合算力有限的场景。（待实现，文献待核查）

**② 两阶段问题中的有界提前停止**（在已有做法基础上的扩展，待验证）：在“先探索、再冲刺”的规则下，只要冲刺路线足够好，探索就可以提前停止。

**已有做法**：开源电脑鼠迷宫库 MicroMouse Maze Library（kerikun11，MIT 许可证）的探索算法分三段：

1. **去程**：把未知墙当作没有墙，规划到目标，沿路线走到含有未知墙的格子时观测并重新规划，直到到达目标；
2. **追加探索**：把未知墙当作没有墙，求起点到目标的最短路，把这条路上还有未知墙的格子作为目的地逐个去确认；**目的地集合为空时停止**，此时最短路上的墙已全部确认，即证明了已知路线就是真正的最短路；
3. **回程**：把未知墙当作**有墙**，只走已确认的路线返回起点。

这一做法相当于下文的 ε = 0。本组在此基础上把“必须证明最优才停”放宽为“误差有界即可停”，思路如下。我们可以同时计算两个最短路长度：

- **乐观长度 O**：把所有未知的边都当作通路；
- **悲观长度 P**：把所有未知的边都当作墙，只走已经确认的通路。

真实最短路长度 L* 一定满足 O ≤ L* ≤ P：乐观地图的边最多，所以最短路最短；悲观地图的边是真实边的一部分，所以最短路最长。于是：

> 当 P ≤ (1 + ε) · O 时停止探索，并沿悲观路线冲刺，冲刺长度 P ≤ (1 + ε) · O ≤ (1 + ε) · L*。

也就是说，**冲刺路线最多比真正的最短路长 ε 倍**。ε = 0 时就是上述已有做法的“证明找到了最短路才停”；ε 越大，停得越早，省下的探索步数越多，但冲刺路线可能稍长。这是一个带误差保证的近似停止准则，可以直接在实验中测量“探索步数 + 冲刺步数”如何随 ε 变化。

是否已有文献提出过相同的 ε 放宽，尚未完成核查；在核查之前，本文只把它称为“本组对已有做法的扩展”，不宣称首创。

### 3.4 感知层与控制层（可选扩展）

- **控制层**：用梯形速度曲线模拟加速和减速，给转弯设固定耗时，把“步数”换成更真实的“时间”。转弯代价 λ 可以从这个模型推出来，不用凭空设定。（README 任务 E1）已有参考：MicroMouse Maze Library 在求最短路时提供按梯形加速列出“直走 n 格所需时间”的代价表，再加上转弯耗时；开源项目 Ariadne（akeanti，MIT 许可证）在“边 × 朝向”状态上用整数时间代价运行 Dijkstra，据其仿真结果，平滑转弯的计划在 200 张随机迷宫上只需原地转弯的 0.56 倍时间（该项目说明尚未在真实迷宫上验证）。
- **感知层**：给每个传感器设定准确率 p，每面墙维护一个对数几率分数 S，观测到“有墙”时加上权重 w = ln(p / (1 − p))，观测到“没墙”时减去 w。越准的传感器权重越大，这与按 1/σ² 给传感器加权的思想相同。（README 任务 E2，需要改动撞墙规则，先在组内讨论）

### 3.5 现实因素与对应技术汇总

| 现实因素 | 技术 | 类型 | 状态 |
| --- | --- | --- | --- |
| 迷宫开阔、需要少搜索 | A* 曼哈顿启发式 | 启发式（保最优） | 已实现 |
| 需要快速朝目标前进 | 贪心邻格排序 | 启发式（不保最优） | 已实现 |
| 算力有限 | 加权 A* | 近似（w 倍界） | 待实现 |
| 计算要实时 | 按需重规划（重复 A*） | 计算优化 | 已实现 |
| 转弯有代价 | （格子, 朝向）上的 Dijkstra / A* | 精确算法 + 启发式 | 待实现 |
| 先探索后冲刺 | ε 提前停止 | 近似（1 + ε 倍界） | 待实现 |
| 评分权重难以设定 | 模拟退火 / 随机搜索调参 | 元启发式 | 待实现 |
| 传感器有噪声 | 对数几率加权融合 | 概率推理 | 待讨论 |

## 4. 新解决方案：代价感知的乐观重规划与有界提前停止

> 状态：**设计方案，待实现与验证**（对应 README 任务 C1 / C2）。以下性质中，有的可以证明，有的只是假设，文中分别注明。
>
> **与已有工作的关系**：本方案的各个组成部分都有前人做法——乐观假设与按需重规划见 MicroMouse Maze Library 的去程探索与重复 A*，状态加朝向的时间代价规划见 MicroMouse Maze Library 与 Ariadne，“证明最短路后停止探索、未知墙视为墙返回”见 MicroMouse Maze Library（即 ε = 0），死路填充是经典的迷宫求解方法。本组的工作在于：把这些部分组合进同一个可对比的框架；把停止准则放宽为误差有界的 ε 版本；并用统一的实验与消融分析各部分的贡献。在完成文献核查前，本方案称为“本组提出的组合与变体”，不宣称首创。

### 4.1 设计动机

第 2、3 章的发现直接决定了方案的组成：

| 发现 | 设计上的回应 |
| --- | --- |
| 乐观规划步数最少、最稳定（发现 2） | 保留“未知边视为通路”的乐观假设 |
| 按需重规划可以省掉大部分计算（发现 3） | 只在计划被新墙挡住时才重新规划 |
| 现实中转弯很贵（3.1） | 在（格子, 朝向）的状态空间上规划，代价 = 1 + λ × 转弯（同类做法见 Ariadne） |
| 启发式效果依赖地图，需要设计得当（发现 5） | 使用不高估代价的“曼哈顿 + 转弯下界”启发式 |
| 比赛是两阶段的（3.3） | 用 ε 准则决定何时停止探索（ε = 0 时即 MicroMouse Maze Library 的追加探索） |
| 死胡同会误导乐观假设（发现 4、6） | 确认的死胡同直接剪掉，不再规划进去（经典死路填充的在线版本） |

### 4.2 方案组成

1. **状态与代价**：状态是（格子, 朝向），共 4V 个。直走一格代价为 1，原地转 90° 代价为 λ。λ 由控制层的运动时间模型推出；λ = 0 时方案退化为重复 A*。
2. **乐观地图上的 A***：未知边视为通路，启发函数 h = 曼哈顿距离 + λ × [当前位置与每个目标格都既不同行也不同列]。h 不会高估真实代价，所以每次规划得到的都是乐观地图上的最优路线。
3. **按需重规划**：每走一步，只检查剩余计划上有没有新发现的墙；有才重新规划。
4. **死路剪枝**：三面是墙、且不是目标的格子标为死胡同；若一个格子除了通向死胡同的边外只剩一个出口，它也成为死胡同，依次向外传递。规划时不再进入死胡同。起点、目标和小车当前所在的格子不剪（起点通常本身就是三面墙）。
5. **ε 提前停止（第二阶段）**：到达目标后，持续计算乐观代价 O 和悲观代价 P。一旦 P ≤ (1 + ε) · O，就停止探索，按悲观路线冲刺。选择下一个要确认的格子时，沿用 MicroMouse Maze Library 的做法：去乐观最短路上还有未知墙的格子。ε = 0 时，本步骤与该库的追加探索等价。

### 4.3 伪代码

```text
初始化：已知墙 K = ∅，计划 plan = 空，阶段 = 探索
每一步（当前状态 (v, θ)，观测到 v 的四面墙）：
    把新观测到的墙加入 K；更新死胡同集合 D
    if 阶段 = 探索 and v ∈ 目标:
        阶段 = 验证
    if 阶段 = 验证:
        O = 乐观代价(起点 → 目标, K)      # 未知边视为通路
        P = 悲观代价(起点 → 目标, K)      # 只走已确认的边
        if P ≤ (1 + ε) · O:
            return 冲刺路线（悲观地图上的最优路线）
        目标点 = 乐观最优路线上第一条未确认的边    # 去看最影响结论的地方
    if plan 为空 or plan 上有边 ∈ K or plan 经过 D:
        plan = A*((v, θ) → 目标点, 乐观地图 \ D, 代价 1 + λ·转弯, 启发 h)
        if plan 不存在: return 无路
    沿 plan 走一步
```

### 4.4 理论性质

- **完备性（可证明）**：迷宫有限，墙也有限。每次重新规划，要么沿计划前进，要么至少新发现一面墙；墙不可能被无限次地发现，所以只要目标可达，算法就一定能在有限步内到达；目标不可达时，乐观地图上的规划终将失败，算法返回无路。
- **冲刺路线的质量（可证明）**：由 3.3 节的不等式，停止时冲刺代价 P ≤ (1 + ε) · L*。
- **单次规划复杂度**：在 4V 个状态上运行 A*，最坏 O(V log V)；按需重规划使大多数步不需要规划。
- **死路剪枝的安全性（待证明）**：需要证明被剪掉的格子不会出现在任何通往目标的更优路线上。初步论证：死胡同只有一个出口，任何经过它的路线都必须原路返回，因此不可能比不经过它的路线更短。

### 4.5 待验证的假设

- **H1**：在有转弯代价的时间模型下，本方案的总用时少于重复 A* 和 Flood-Fill。
- **H2**：死路剪枝能减少重复访问，在死胡同多的迷宫（如比赛迷宫、无环迷宫）上效果更明显。
- **H3**：随着 ε 增大，“探索步数 + 冲刺步数”先下降后上升，存在一个较好的取值区间。

### 4.6 评估计划

- **消融实验**：依次去掉转弯代价、按需重规划、死路剪枝、ε 停止，各自衡量贡献。
- **对照组**：重复 A*、Flood-Fill、DFS，以及作为参照的已知地图最短路。
- **指标**：探索步数、冲刺步数、总时间（依据运动模型）、转向次数、计算时间、重新规划次数。
- **数据划分**：在开发地图上选择 λ 与 ε，冻结后在测试地图上评估；测试地图包含比赛迷宫与多种生成器生成的地图，并记录种子。
