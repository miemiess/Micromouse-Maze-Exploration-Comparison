# 未知迷宫中电脑鼠探索算法的比较与分析：问题建模与算法选择

> **文档状态**　中文初稿，2026-11-22 更新。
> 第 2 章的数据来自按实验计划运行的正式实验（`results/basic/`，514 张地图 × 13 个算法，其中 4 个是第 4 章新方案及其消融变体）。
> 第 4 章新方案与其他算法在同一次基础实验中运行，参数在开发集上选定。第 3 章的扩展实验（X1～X4）按运行前冻结的[扩展实验计划](ext/experiment-plan.md)完成，数据见 `results/ext/`，配对检验与曲线由 `src/ext/analysis.py` 生成（`results/ext/analysis/report.md`）。

## 摘要

本项目研究一个经典的 AI 问题：**一辆小车（电脑鼠）在事先不知道地图的迷宫中，只能边走边看，如何尽快到达目标？**
我们按计算思维的步骤推进：先把现实问题**抽象**成“未知图上的在线寻路”，再**分解**为“记录已知信息、选择下一步、判断何时停止”三个子问题，通过**模式识别**把它与图遍历、最短路等已知问题联系起来，然后**设计**并实现了 7 个探索算法和 2 个已知地图参照算法。
基础实验覆盖 514 张迷宫，包括 394 张外部地图和 120 张由四种算法生成的地图。在单位移动代价和理想观测下，重复 A* 与 Flood-Fill 均在全部地图上到达目标，在七种已有探索算法中总体平均步数比最低，分别为 2.172 和 2.303。按表 2 的四类地图汇总，重复 A* 的计算时间中位数约为 Flood-Fill 的 1/15～1/21。算法的相对表现随迷宫的生成方式和环路比例变化。
我们还提出并实现了一个新方案：**先验增强的重复 A***（柱子规则推断墙 + 按墙密度自适应的未知边惩罚）。完整的消融实验显示，它在生成迷宫上有所改善，在外部迷宫库上却整体变差，只降低了最坏情况；结构先验在理想观测下几乎不改变决策。这个负面结果揭示了开发集与测试集之间的分布偏移。最后，我们放宽假设，逐层加入转弯代价、运动时间、传感器噪声和“先探索、再冲刺”的两阶段比赛规则，在按地图来源分层的 435 张测试图上运行了事先冻结的对照实验。规则更接近现实后，乐观重规划仍然最好；把转弯纳入规划、增量修复（D* Lite）和置信度融合都没有带来显著收益，加权 A* 显著减少了搜索量，而代价没有显著变化。两阶段比赛中，“证明找到最短路再冲刺”的追加探索在外部迷宫库上显著优于“到达即停”，在生成图上差异不显著；本组提出的误差有界提前停止（ε > 0）在每张地图上都满足冲刺代价 ≤ (1 + ε) 倍最优，但在当前成绩公式（探索代价折算 1/30）下平均成绩没有更好；事后验证表明，探索折算得越重，ε > 0 越有利。

## 1. 现实问题与计算思维建模

### 1.1 现实问题

很多真实系统都要在**信息不完整的环境中做决策**：

- 扫地机器人第一次进入一个新房子，不知道户型；
- 仓库机器人或无人机遇到货架挪动、通道被堵，需要改道；
- 搜救机器人在结构未知的废墟中寻找被困者；
- 电脑鼠比赛：小车被放进一个从未见过的 16×16 迷宫，要尽快找到中央的目标区。

它们的共同点是：**地图只能边走边了解，而每一步移动都有代价**。走得越多，耗电越多、时间越长；算得越久，反应越慢。本项目以电脑鼠为原型研究这一类问题。

### 1.2 从最简单的情形开始：抽象

计算思维的第一步是抽象：保留与“决策”相关的本质，去掉其他细节。我们先考虑**最简单的情形**：一个简单的迷宫，一辆不分层（不单独考虑传感器和电机）、每走一格代价都为 1 的小车。

| 现实世界 | 抽象后的模型 | 有意忽略的细节 |
| --- | --- | --- |
| 迷宫场地 | W×H 的网格；格子是图的**节点** | 尺寸、材质 |
| 通道与墙 | 相邻两格之间没有墙就连一条**边**；墙 = 删掉这条边 | 墙的厚度、安装误差 |
| 红外传感器 | **理想观测**：到达一格后，准确知道它四个方向有没有墙 | 噪声、误判、视野限制 |
| 电机运动 | **走一格 = 1 步**；转向单独计数，不影响代价 | 加减速、打滑、转弯耗时 |
| 小车的位置 | 准确知道自己在哪一格、朝哪个方向 | 定位误差 |

这些抽象是**有意的设计选择**：只保留决策层，就能保证实验中观察到的差异只来自算法本身，而不是传感器噪声或电机误差（相当于控制变量）。第 3 章再逐步把被忽略的因素加回来。

### 1.3 问题形式化

把迷宫看成一个无向图 G = (V, E)，|V| = W × H。

| 要素 | 定义 |
| --- | --- |
| 输入 | 网格尺寸 W、H，起点 s，起始朝向，目标集合 T（16×16 时为中央 2×2）。**边集 E 一开始未知** |
| 观测 | 小车到达格子 v 后，得知 v 的四条边中哪些存在 |
| 动作 | 每一步移动到一个相邻且无墙的格子（北、东、南、西四个方向之一） |
| 目标 | 到达 T 中任意一格，并使移动步数尽量少 |
| 次要指标 | 转向次数、重复访问次数、算法计算时间 |
| 终止 | 到达目标；或算法声明无路；或超出移动预算（20 × 格子数）；或计算超时（30 秒） |

这是一个**在线问题**：算法每一步都必须在只知道部分地图的情况下做决定，不能先看完整地图再规划。与之对应的**离线问题**（一开始就知道 E）就是普通的图最短路问题，可以用 BFS 精确求解。离线最优解是衡量在线算法的参照：

> **竞争比（本文称“步数 / 最短路”）** = 在线算法的实际步数 ÷ 已知地图下的最短路长度，越接近 1 越好。

### 1.4 分解：把问题拆开

任何探索算法都要回答三个子问题：

1. **记住什么？**（知识表示）：什么都不记 / 记住去过哪里 / 记住看到的每一面墙；
2. **下一步去哪？**（决策规则）：局部规则 / 系统地遍历 / 先假设地图再规划；
3. **什么时候停？**（终止条件）：到达目标、确认无路、发现陷入循环。

项目实现也按同样的方式分解，各部分独立、可替换：

| 模块 | 职责 | 文件 |
| --- | --- | --- |
| 环境 | 持有真实地图，提供观测，执行移动，统计步数与转向 | `src/core/environment.py` |
| 算法 | **只**回答“下一步往哪走”，看不到真实地图 | `src/basic/algorithms/dfs.py` 等，每个算法一个文件 |
| 统一接口与驱动 | 发现算法、按统一规则运行和计时 | `src/core/algorithm_api.py` |
| 可视化与实验 | 上位机演示、批量实验 | `tools/MazesTest/`、`results/` |

### 1.5 模式识别：与已知问题建立联系

- **已知地图时**：在单位代价的图上找最短路，就是 **BFS**；加上启发式就是 **A***。
- **完全不记忆时**：只能靠局部规则，例如沿墙走，这是一个**有限状态机**。
- **记住访问过的格子时**：系统地走遍所有可达格子，就是**图的深度优先遍历（DFS）**，只是回溯必须真实地走回去。
- **记住墙并做假设时**：把未知的边**乐观地**当作通路，问题又变回已知地图上的最短路。每发现一面新墙，就修正地图、重新规划。**Flood-Fill 本质上就是从目标出发的 BFS**，所以不能把“BFS”和“Flood-Fill”当成两种无关的方案。

由此得到三类策略，对应“记住什么”的三种选择：

| 策略族 | 记忆 | 代表算法 |
| --- | --- | --- |
| 局部规则 | 不记地图 | 随机游走、沿墙法 |
| 系统遍历 | 记住访问过的格子 | DFS、贪心 DFS |
| 乐观规划 | 记住所有看到的墙，并假设未知边可通行 | Flood-Fill、重复 A* |

### 1.6 好算法应该满足什么

在设计具体算法之前，先明确要求：

1. **不偷看**：探索算法只能使用观测，不能读取真实地图。这一点由接口强制保证。
2. **必定终止**：在有限迷宫中，要么到达目标，要么在有限步内声明无路，不能无限循环。
3. **规则无歧义**：平局时选哪个方向必须写清楚，保证结果可以复现。
4. **可度量**：步数、转向、计算时间分开统计，**移动成本和计算成本不能混为一谈**。

## 2. 候选算法与当前环境下的对比

### 2.1 候选算法与选择理由

每个算法都有一个**纳入比较的理由**，而不是越多越好。完整的登记（信息假设、平局规则、失败条件、复杂度）见 [`Docs/basic/algorithm-methods.md`](basic/algorithm-methods.md)。

| 算法 | 类别 | 核心规则 | 为什么纳入 |
| --- | --- | --- | --- |
| 随机游走 | 局部规则 | 在无墙方向中随机选 | **下界**：衡量“有策略”比“没策略”好多少 |
| 沿墙法（左 / 右手） | 局部规则 | 始终贴着一侧墙走；（位置, 朝向）重复即判定循环 | 最简单、几乎零计算；检验“不记忆地图”的极限 |
| DFS＋实际回溯 | 系统遍历 | 按北东南西选未访问邻格，走不通就原路退回 | 保证走遍所有可达格子（完备），不依赖任何假设 |
| 贪心 DFS | 系统遍历 | 同 DFS，只是优先选离目标近的邻格 | **消融对照**：只改一个排序规则，看目标方向的启发式有多大作用 |
| Flood-Fill | 乐观规划 | 未知边视为通路，每步从目标做 BFS 全量重算距离，走向距离最小的邻格 | 电脑鼠比赛的经典方法 |
| 重复 A* | 乐观规划 | 与 Flood-Fill 假设相同，但只在计划被新墙挡住时才从当前位置用 A* 重新规划 | 与 Flood-Fill 比较“同样的假设、不同的计算方式” |
| BFS（已知地图） | 参照 | 一开始就知道完整地图 | 给出最短路，用来计算“步数 / 最短路” |
| A*（已知地图） | 参照 | 曼哈顿距离启发式 | 与 BFS 比较启发式能少搜多少格子 |

两点说明：

- **为什么没有单独实现 Dijkstra**：在每步代价为 1 的图上，Dijkstra 与 BFS 完全等价。它只有在引入转弯代价（第 3 章）后才有独立意义。
- **已知地图算法不参与排名**：它们看得到完整地图，只作为参照，与探索算法分开比较。

### 2.2 复杂度

V 为格子数（16×16 时为 256），E 为无墙的相邻边数（E ≤ 2V）。

| 算法 | 每一步的计算量 | 移动步数 | 额外内存 |
| --- | --- | --- | --- |
| 随机游走 | O(1) | 无上界，由预算截断 | O(1) |
| 沿墙法 | O(1) | 最多 4V 次决策就会到达目标或判定循环 | O(V) |
| DFS / 贪心 DFS | O(1) | ≤ 2 × 可达格子数 | O(V) |
| Flood-Fill | O(V + E)（**每一步**都全量重算） | 实验统计 | O(V) |
| 重复 A* | 只在被挡住时规划，单次最坏 O(V log V)；其余步只检查计划 | 实验统计 | O(V) |
| BFS / A*（已知地图） | 只规划一次：O(V + E) / O(V log V) | 等于最短路长度 | O(V) |

两个需要说明的地方：

- **沿墙法为什么一定会停**：它的下一步只取决于（位置, 朝向），一共只有 4V 种状态。按抽屉原理，最多 4V 步后状态必然重复；而状态一旦重复，之后的路线就会无限循环。所以只要检测到状态重复就可以停止，这同时证明了它必定终止。
- **单步复杂度 ≠ 总复杂度**：探索算法的总计算量是“每步计算量 × 决策次数”，不能把一次 BFS 的复杂度当作整段探索的成本。

### 2.5 分析

**发现 1：迷宫结构决定算法的优劣，没有“永远最好”的算法。**
沿墙法在 40 张无环生成迷宫上全部成功，环路比例升到 10% 时只有 13/40，30% 时只剩 2/40；在外部迷宫库上只有 89/394（23%）；失败全部记为 `loop_detected`（判定陷入循环），与“声明无路”的 `no_path` 分开统计。原因可以从理论上解释：没有环路时，所有墙都与外墙连成一片，贴着一侧墙走一定能走遍整个迷宫；一旦出现环路，目标就可能落在不与外墙相连的“孤岛”上，沿墙法只会绕着外圈打转。比赛迷宫的中央目标正是这样设计的。即使在它能成功的无环迷宫上，沿墙法的步数也约为最短路的 8～9 倍，因为它不利用任何目标信息。

**发现 2　两种乐观规划算法均在全部地图上到达目标**
按全部地图汇总，Flood-Fill 和重复 A* 的平均步数比分别为 2.303 和 2.172，在七种已有探索算法中最低。细分地图组的排名会变化。例如在 30% 环路的 Kruskal 地图上，重复 A* 和贪心 DFS 的平均步数比分别为 1.335 和 1.362，位居前两名。Flood-Fill 和重复 A* 都会记住已观测的墙，并在发现障碍后修正路线。两者平均转向约 56 次，平均重复访问约 17～18 次。

**发现 3　重复 A* 在当前实现中的实测计算时间更短**
按表 2 的四类地图汇总，重复 A* 的计算时间中位数约为 Flood-Fill 的 1/15～1/21。在外部迷宫库上，两者分别为 2.77 和 42.14 毫秒。逐图比较时，重复 A* 在 514 张地图上的计时均更短，其中 41 张的加速不足 10 倍。Flood-Fill 每步重新传播距离，重复 A* 缓存路线，遇到新墙挡路时才重新搜索。

两种方法在外部迷宫库的平均步数比接近，分别为 2.17 和 2.31。逐张比较 394 张外部地图，重复 A* 的步数更少、相同、更多的地图数分别为 179、94、121。

**发现 4：不利用目标信息的 DFS 随环路增加而退化，目标启发式能扭转这一趋势。**
DFS 的“步数 / 最短路”从无环迷宫的 7.35 恶化到 30% 环路时的 11.37：环路越多，最短路越短（平均从 33.4 降到 14.6），但 DFS 按固定方向顺序遍历，经常先钻进远离目标的区域。贪心 DFS 只改了一个排序规则，趋势正好相反：从 5.08 降到 2.03。这个消融对照说明**目标方向的启发式在开阔迷宫中价值很大**。在外部迷宫库上，贪心 DFS 在 277/394 张地图上少于 DFS，但仍有约 30% 的地图被“看起来离目标近”的方向误导进死路。

**发现 5：启发式的效果取决于地图结构。**
A* 与 BFS 找到的最短路长度完全相同（单位代价下必然如此），只有扩展的节点数不同。在外部迷宫库上，A* 只比 BFS 少扩展 10%；环路越多，节省越大：无环 33%、10% 环路 55%、30% 环路 69%。原因是走廊曲折时，曼哈顿距离严重低估真实距离，启发式几乎提供不了方向信息；迷宫越开阔，曼哈顿距离越接近真实距离。

**发现 6：生成器的选择会改变结论（已用正式数据证实）。**
同为无环迷宫，不同生成器的结果差别很大：

| 生成器（无环，各 10 张） | 死胡同数（种子 1） | Flood-Fill 均值 | 恰好最优 | 重复 A* | DFS | 贪心 DFS |
| --- | --- | --- | --- | --- | --- | --- |
| 递归回溯 | 28 | 1.00 | 10/10 | 1.00 | 1.19 | 1.12 |
| Wilson（无偏） | 78 | 4.62 | 1/10 | 2.93 | 6.06 | 7.76 |
| 随机 Prim | 80 | 5.18 | 0/10 | 5.75 | 11.87 | 9.61 |
| 随机 Kruskal | 74 | 1.57 | 1/10 | 1.70 | 10.28 | 1.82 |

递归回溯生成的迷宫走廊长、死胡同少（只有其他生成器的三分之一左右），乐观规划在这种结构上几乎不会被误导；换成无偏的 Wilson 生成器后，Flood-Fill 平均要走最短路的 4.6 倍。初稿只用了递归回溯，因此得出了过于乐观的结论。这说明**只用一种生成器得到的结论可能完全不成立**，本次正式实验因此同时使用了 4 种生成器和 394 张外部迷宫库地图。

**随机游走与随机性。** 随机游走作为下界，在外部迷宫库上只有一半在预算内到达，成功的运行也要走最短路的 44 倍（中位数）；它的平均值只统计成功的运行，存在幸存者偏差。随机性实验中，同一张地图换 10 个种子，成功次数只有 1～3 次，成功时的步数在 2757～4891 之间，说明随机算法的单次结果几乎没有参考价值，必须用多个种子报告分布。所有确定性算法的 3 次重复运行路线完全一致。

### 2.6 当前环境下的算法选择结论

在“每步代价为 1、观测准确”的基础环境中：

| 场景 | 推荐 | 理由 |
| --- | --- | --- |
| 一般的未知迷宫（包括外部迷宫库） | **重复 A*** | 514/514 成功，七种已有探索算法中总体平均步数比最低（2.172），低于第 4 章完整版的 2.318。表 2 各类地图上的计算时间中位数较低。 |
| 需要格子距离值 | Flood-Fill | 总体平均步数比为 2.303，可保留格子距离值。当前实现每步重新传播距离，实测计算时间较长。 |
| 只要求一定走遍、不在乎步数 | DFS | 不依赖任何假设，保证访问所有可达格子；但步数随环路增加迅速变差 |
| 算力和内存极其有限，且已知迷宫无环 | 沿墙法 | 几乎不需要计算和内存，在无环迷宫上必定成功；但步数是最短路的 8～9 倍，有环路时大多失败 |
| 需要一个参照标准 | BFS / A*（已知地图） | 给出最短路，用于计算“步数 / 最短路”；A* 在开阔地图上能显著减少搜索 |

需要强调的是，这个结论依赖于基础环境的假设。代价规则一变（例如转弯很贵），最优选择就可能改变，这正是第 3 章要讨论的。

### 2.7 有效性威胁

- **地图来源**：外部迷宫库来自同一个上游集合，以比赛迷宫为主，但也混有少量测试 / 练习图（如几乎无墙的 `external_empty`），因此本文不把它称为“真实比赛迷宫”；上游说明数据可能有错误；导入时已排除无法转换、目标不可达和重复的地图。生成迷宫只有 4 种生成器，其他结构（例如房间型地图）未覆盖。
- **统计方式**：均值受少数极端地图影响很大，因此同时报告中位数；成功率与比值分开报告，失败的运行没有被丢弃。
- **理想化假设**：观测准确、单位代价，这些假设对结论的影响要在第 3 章的扩展实验中检验。
- **计时依赖机器**：计算时间受 Python 版本和机器影响，只能用于同一台机器上的相对比较；每个组合重复 3 次取中位数以减少波动。
- **代码版本**：每个结果目录的 `metadata.json` 记录了运行时的提交号；带 `+dirty` 表示运行时有未提交的代码改动，定稿前应在干净的提交上重新运行一次。

## 3. 走向现实：放宽假设，引入启发式与近似算法

### 3.1 模型与现实的差距

| 第 1 章的假设 | 现实情况 | 放宽后带来的新问题 |
| --- | --- | --- |
| 每一步代价相同 | 转弯要减速，直线可以加速 | “最短”不再等于“最快”，需要按时间或加权代价规划 |
| 观测准确 | 红外传感器会误报和漏报 | 墙的存在变成概率，需要融合多次观测 |
| 计算不受限 | 小车上的单片机算力有限，要实时决策 | 精确算法可能来不及算完 |
| 只要到达目标 | 比赛规则是先探索、再冲刺 | 要决定**探索到什么程度就可以停** |
| 迷宫只有 16×16 | 仓库、楼宇的地图大得多 | 每步全量重算的成本迅速增长 |

当问题变得更真实，**精确最优**往往要么算不起，要么没法定义。这时就需要两类工具：

- **启发式算法**：用经验规则引导搜索，通常更快，但**不保证**结果的质量；
- **近似算法**：用一部分最优性换取效率，但能**证明**结果与最优解的差距不超过某个界限。

### 3.2 启发式

基础阶段用到了两种启发式，它们的效果都可以直接测量：

- **A* 的曼哈顿距离启发式**：不会高估真实距离（可采纳），所以 A* 仍能保证找到最短路。发现 5 表明它的效果取决于地图结构。
- **贪心 DFS 的邻格排序**：优先选离目标近的方向，不保证最优，但在开阔迷宫上大幅减少了步数（发现 4）。

扩展阶段的 `turn_aware_astar` 把朝向纳入搜索状态。以转弯代价为例，目标与当前位置既不同行也不同列时，至少要转一次弯。算法将行进代价下界与必要转向代价下界相加，在当前乐观地图上寻找最优路线；沿途发现墙阻断剩余路线时再规划。整局走过的路还包括发现障碍之前的移动。X1 中它与重复 A* 逐图胜负接近，没有显著差异（3.7、3.8 节）。

另一类启发式是**加权评分**：把目标距离、预计转弯、重复访问、能获得的新信息等因素加权求和，用来给候选方向打分。这些权重无法用梯度方法求解，因为“权重 → 平均步数”的关系呈台阶状、不可微，而且有很多局部最优；适合用**元启发式**（随机搜索、模拟退火）在开发地图上调参，冻结后再到测试地图上评估。（待实现）

### 3.3 近似算法

**① 加权 A*（已实现）**。变体 `turn_aware_astar_w2` 使用 f = g + 2h。在当前乐观地图上的一次搜索中，返回路线的代价至多为该图最优代价的两倍。整局探索会经历多次观测和重规划，累计代价需另行测量。X1 中，它在所有规则下扩展状态数都显著少于 w = 1（λ = 2 时平均 1188 对 1371，约少 13%），整局代价没有显著差异（3.7 节）。

**② 两阶段问题中的有界提前停止**（D5，已实现：`src/ext/rules/two_phase.py`、`src/ext/algorithms/bounded_explore.py`；X3 已评估）：在“先探索、再冲刺”的规则下，只要冲刺路线足够好，探索就可以提前停止。

**已有做法**：开源电脑鼠迷宫库 MicroMouse Maze Library（kerikun11，MIT 许可证）的探索算法分三段：

1. **去程**：把未知墙当作没有墙，规划到目标，沿路线走到含有未知墙的格子时观测并重新规划，直到到达目标；
2. **追加探索**：把未知墙当作没有墙，求起点到目标的最短路，把这条路上还有未知墙的格子作为目的地逐个去确认；**目的地集合为空时停止**，此时最短路上的墙已全部确认，即证明了已知路线就是真正的最短路；
3. **回程**：把未知墙当作**有墙**，只走已确认的路线返回起点。

这一做法相当于下文的 ε = 0。本组在此基础上把“必须证明最优才停”放宽为“误差有界即可停”，思路如下。我们可以同时计算两个最短路长度：

- **乐观长度 O**：把所有未知的边都当作通路；
- **悲观长度 P**：把所有未知的边都当作墙，只走已经确认的通路。

真实最短路长度 L* 一定满足 O ≤ L* ≤ P：乐观地图的边最多，所以最短路最短；悲观地图的边是真实边的一部分，所以最短路最长。于是：

> 当 P ≤ (1 + ε) · O 时停止探索，并沿悲观路线冲刺，冲刺长度 P ≤ (1 + ε) · O ≤ (1 + ε) · L*。

也就是说，**冲刺路线长度至多为真实最短路长度的 1 + ε 倍**。ε = 0 时就是上述已有做法的“证明找到了最短路才停”；增大 ε 会放宽停止条件。在同一条探索轨迹上，系统可以更早满足判据。这是一个带误差保证的近似停止准则。X3 测量了探索代价、冲刺代价与成绩随 ε 的变化（3.7 节）：探索代价确实随 ε 下降，但在当前成绩公式下，冲刺变长带来的损失更大，ε = 0 的平均成绩最好；探索折算更重时 ε > 0 更好（发现 12）。

是否已有文献提出过相同的 ε 放宽，尚未完成核查；在核查之前，本文只把它称为“本组对已有做法的扩展”，不宣称首创。

### 3.4 感知层与控制层

- **控制层（E1 已实现）**：用梯形速度曲线模拟加速和减速，给转弯设固定耗时，把“步数”换成更真实的“时间”。转弯代价 λ 可以从这个模型推出来，不用凭空设定。格长取 0.18 m，默认速度、加速度及转向用时是待实测校准的仿真假设。已有参考：MicroMouse Maze Library 在求最短路时提供按梯形加速列出“直走 n 格所需时间”的代价表，再加上转弯耗时；开源项目 Ariadne（akeanti，MIT 许可证）在“边 × 朝向”状态上用整数时间代价运行 Dijkstra，据其仿真结果，平滑转弯的计划在 200 张随机迷宫上只需原地转弯的 0.56 倍时间（该项目说明尚未在真实迷宫上验证）。
- **感知层**：给每个传感器设定准确率 p，每面墙维护一个对数几率分数 S，观测到“有墙”时加上权重 w = ln(p / (1 − p))，观测到“没墙”时减去 w。准确率越高，单次读数提供的证据权重越大。E2 已实现这一融合方法。默认前、侧、后准确率分别为 0.95、0.90、0.85，均为待校准的仿真假设。X2 用 5 个噪声种子比较了置信度重规划与只信最近读数的消融（3.7 节）。
- **碰撞策略（已实现）**：可以在首次撞墙时终止、撞墙后继续，或在累计达到上限时终止。可恢复碰撞消耗一次动作预算。电脑鼠留在原格，朝向更新为尝试方向，并获得该方向有墙的接触反馈。

### 3.8 分析

**发现 7：在未知地图上，按规则代价规划没有带来可测的好处。** 朝向 A* 每次重规划得到的路线，对当前的乐观地图是规则代价最优的；但整局代价主要来自乐观假设被推翻后的绕路，理想观测下“步数 / 最短路”已在 2.2 左右，转弯只是其上的一小项。为了少转弯，朝向 A* 会选另一条路线，这条路线被墙堵住的机会时多时少，所以逐图胜负接近（λ = 2 时 186 胜 / 168 负）；平均代价比反而略高（2.642 对 2.586），说明少数地图上的损失更大。λ 从 0.5 增大到 4，胜负比例没有出现系统的变化。这与基础阶段的结论一致：**乐观假设带来的误导，比局部路线的好坏重要得多**。

**发现 8：排名基本不变。** 各档规则下，前三名都是乐观重规划类算法（重复 A*、加权朝向 A*、Flood-Fill、D* Lite），DFS、沿墙法、前沿探索始终最差，λ 越大差距越大（DFS 从 6.7 升到 8.5）。λ ≥ 2 时第一名名义上从重复 A* 变成加权朝向 A*，但两者平均值只差 1%～2%，加权朝向 A* 与 w = 1 的配对也没有显著差异；按计划只说“最优算法名义上改变”，不据此改变推荐。

**发现 9：加权 A* 的近似在这里几乎不花代价。** w = 2 在每档规则下都显著减少扩展状态数，λ = 2 时约少 13%，计算时间中位数从 13.2 ms 降到 10.4 ms；代价比没有显著差异，且 52%～66% 的地图上两者代价完全相同。原因可能是：在稀疏墙壁的乐观地图上，可采纳启发式本来就接近真实代价，放大 h 主要只是改变同代价路线之间的选择。

**发现 10：小地图上增量搜索不划算。** D* Lite 的计算时间在几乎每张地图上都比重复 A* 长（中位数 5.2 ms 对 2.1 ms），路线在 78% 的地图上相同。16×16 地图上每次从头搜索本来就很便宜，D* Lite 维护 rhs 值和优先队列键的额外开销超过了它省下的扩展。这一结论只适用于本文的 Python 实现和 16×16 地图；增量搜索的优势预计在更大的地图上才会显现，本文没有验证。

**发现 11：噪声下，累积证据的好处被兜底规划抵消；传感器质量比算法选择更重要。** 即使是准确率最高的一档（0.95 / 0.90 / 0.85），步数比也从 2.14 升到约 3.8，每局撞墙约 20 次；而同一档噪声下两种算法的步数差异都不显著。为了解释原因，我们做了事后验证（`python src/ext/posthoc.py contact` → `results/ext/posthoc/contact.md`；与 X2 相同的地图与种子，6000 次运行与 X2 逐条一致），检验两个假设。

- **假设 A：确定的接触反馈替代了累积证据**（撞到的墙记为确定有墙，错误的“无墙”信念一撞就纠正）。检验方法是去掉接触反馈：撞墙后只得到普通的噪声读数（200 张地图 × 种子 0）。若假设成立，去掉后融合应明显好于只信最近读数。**结果不支持**：两种算法都大面积失败（成功率从 100% 降到高 / 中 / 低三档的约 56%、35%、20%，每局撞墙数千次），两者的步数比仍无显著差异，融合的撞墙在高、中两档反而显著更多。原因是兜底规划只把确定的墙当墙，没有接触反馈就没有确定的墙，兜底路线会反复撞墙（融合 99.8%、只信最近读数 84%～94% 的撞墙发生在兜底路线上）。这个消融说明**接触反馈是噪声下能到达终点的前提**，但不能说明融合为什么没有优势。
- **假设 B：融合的好处被兜底规划抵消。** 算法在“更可能有墙”的地图上找不到路时，会退回到只把确定的墙当墙的兜底规划，兜底路线无视全部读数。把撞墙按发生在正常路线还是兜底路线上分解（有接触反馈，按地图 × 种子配对）：

| 噪声 | 正常路线上的撞墙（融合 / 最近读数） | 兜底路线上的撞墙 | 兜底规划占重规划的比例（每局均值） |
| --- | --- | --- | --- |
| 高 | 4.9 / 5.0，无显著差异 | 16.1 / 15.2，无显著差异 | 0.24 / 0.22，**融合更多** |
| 中 | 11.8 / 13.0，**融合更少**（p < 10⁻⁵） | 22.7 / 20.9，**融合更多**（p = 0.02） | 0.36 / 0.32，**融合更多** |
| 低 | 21.4 / 23.5，**融合更少**（p < 10⁻⁴） | 26.6 / 22.5，**融合更多**（p < 10⁻⁹） | 0.44 / 0.37，**融合更多** |

**结果支持假设 B**：在正常规划中，累积证据确实起作用，中、低两档的撞墙显著更少；但融合更频繁地让乐观地图“断开”，进入兜底规划的比例显著更高，兜底路线上多出的撞墙抵消甚至超过了这部分收益。可能的原因是：低准确率时单次读数的证据权重很小（后方 0.60 时 w ≈ 0.41），一条通路被误读成墙后，融合需要多次相反的读数才能纠正，于是地图更容易断开；只信最近读数下一次读对就恢复（这一机制本身没有单独测量）。由此得到一个明确的改进方向：兜底时不应退回到“无视全部读数”，而应按置信度给边加代价（例如代价随 P(有墙) 增大），而不是二值地当墙或不当墙。这一改进没有实现，留作后续工作。

**发现 12：两阶段比赛中，“确认”比“快到达”更重要。** 到达即停时，冲刺只能走探索中确认过的路线，比最优长 21%～26%；ε = 0 的追加探索平均多花约 47 步探索（成绩中折算为约 1.6），把冲刺缩短到最优，成绩从约 61 降到 54。这一做法就是 3.3 节引用的已有三段式探索，本组的贡献在于测量了它的收益与分布。**本组提出的 ε > 0 放宽，在当前计分下平均成绩没有更好**：ε 从 0 增到 0.25，探索代价下降约 19 步（成绩中只值约 0.6），冲刺变长约 2.1 步，平均成绩变差。但均值掩盖了分布：λ = 2 时，ε = 0.1 在 194 张地图上成绩好于 ε = 0，只有 108 张更差（p < 10⁻⁶，两组方向一致；这是事后比较，不在冻结计划中）。收益小而分散，损失集中在少数地图上。

**事后验证：探索折算系数 D**（`python src/ext/posthoc.py divisor` → `results/ext/posthoc/divisor.md`）。成绩 = 冲刺 + 探索 / D，正式实验取 D = 30。算法的停止判据只取决于 ε、不读 D，所以用 X3 的数据重算成绩，与重新运行完全相同。

| D | 步数代价：平均成绩最好 | λ = 2：平均成绩最好 | ε = 0 vs 重复 A*（步数代价，配对） |
| --- | --- | --- | --- |
| 1、2、4 | 到达即停 | 到达即停 | 更差 |
| 6 | ε = 0.25 | ε = 0.25 | 更差（179/231） |
| 8、10 | ε = 0.1 | ε = 0.25 | 无显著差异 |
| 15、20 | ε = 0 | ε = 0.1 | 取决于地图来源 |
| 30、60、100 | ε = 0 | ε = 0 | 取决于地图来源 |

按均值计算的盈亏点（D 小于它时前者的平均成绩更好）：步数代价下 ε = 0.1、0.25 相对 ε = 0 分别为 D ≈ 14、9，λ = 2 下为 21、14；到达即停相对 ε = 0 为 5.5、7.0。规律与推算一致：**探索越贵（D 越小），越应该少探索**。D 很小时到达即停最好，D 居中时 ε > 0 最好，D 较大时 ε = 0 最好。转弯代价让每一步探索更贵，ε > 0 有利的区间也随之变宽。因此 ε 不是“越小越好”，而应按比赛的计分方式选择。

**发现 13：迷宫来源再次决定结论。** X3 中，外部迷宫库上到达即停的冲刺离最优较远（约 1.24 倍），追加探索收益大、几乎所有比较都显著；生成图上第一次到达的路线已经接近最优（约 1.13～1.15 倍），追加探索平均仍更好，但逐图胜负接近，收益集中在少数地图上。这与第 2 章发现 6、第 4.5 节的分布偏移是同一个现象：只用一种来源的地图，会得出过于乐观或过于悲观的结论。

**发现 14：单一结构特征解释不了乐观算法的表现；对抗迷宫利用的往往是实现细节。** 对重复 A* 和 Flood-Fill，死胡同比例的相关最强（+0.26、+0.23），环路比例弱负相关（−0.16、−0.17），符合直觉：死胡同越多，乐观路线越容易被引进死胡同；环路越多，路线被堵后越容易找到近的替代路线。但这些相关都很弱（|ρ| ≤ 0.26）。DFS 与沿墙法的相关更强，其中沿墙法只统计成功运行，有选择偏差。对抗迷宫说明了另一面：针对重复 A* 生成的迷宫让它的比值升到 24.7，同样采用乐观假设的 Flood-Fill 和朝向 A* 却仍为 1.0，说明这个陷阱利用的是重复 A* 在同代价路线之间的选路顺序，而不是乐观假设本身；针对 Flood-Fill 生成的迷宫对所有算法都难，更接近利用乐观假设本身。对抗迷宫只要求连通，不一定符合比赛规程（例如柱子规则），只作为案例。

### 3.9 扩展规则下的算法选择

| 场景 | 推荐 | 依据 |
| --- | --- | --- |
| 一般情况（任意 λ 或运动时间） | 重复 A*，Flood-Fill 次之 | 发现 7、8：懂规则的规划没有显著收益，重复 A* 计算最快 |
| 算力受限、在意搜索量 | 加权朝向 A*（w = 2） | 发现 9：搜索量显著减少，代价无显著变化 |
| 16×16 地图上的增量搜索 | 不推荐 D* Lite | 发现 10：路线大多相同，计算更慢 |
| 传感器有噪声 | 任一乐观重规划算法，必须利用接触反馈；优先提高传感器准确率 | 发现 11：两种观测处理差异不显著，噪声本身影响大得多 |
| 先探索、再冲刺的比赛 | 按计分选 ε：探索折算 1/30 左右时追加探索到证明最短路（ε = 0）；探索较贵（D 约 6～10）时取 ε = 0.1～0.25；探索很贵（D ≤ 4）时到达即停 | 发现 12、13 与事后验证 |

与第 2.6 节相比，结论的主体没有变：**乐观假设 + 按需重规划**在所有规则下都是首选。扩展规则改变的是“何时停止探索”，而不是“如何选下一步”。

### 3.10 扩展实验的有效性威胁

- **仿真参数**：运动模型（速度、加速度、转向用时）与传感器准确率都是未经实测校准的假设值；噪声按每次读数独立生成，真实传感器的误差往往在时间和空间上相关。成绩公式中的 30 也是假设值，发现 12 中 ε 的结论依赖它（事后验证给出了 D = 1～100 的结果）。
- **多重比较**：本章做了数十组符号检验，没有做多重比较校正。主要结论或者 p 值极小（Q3、Q4、Q7 外部迷宫库），或者本来就是“无显著差异”，不受影响；p 值接近 0.05 的个别比较（如 X3 生成图上的几组）应谨慎解读。
- **地图复用**：外部迷宫库地图在基础阶段已用过，但扩展规则下的结果在计划冻结前没有看过；测试集划分由固定种子计算（`mazes/splits/ext_dev.json`）。
- **计时**：D* Lite 与重复 A* 的计算时间对比依赖本文的 Python 实现与机器，只作同机相对比较。
- **代码版本**：各子实验 `metadata.json` 中的提交号不同，原因是运行期间仓库新增了分析脚本与上位机改动；已核对 `src/` 与 `mazes/` 中只新增了分析脚本，算法与规则代码与冻结提交 `e6e5e8e` 相同。

## 4. 新解决方案：先验增强的重复 A*（基础规则下）

> 状态：**已实现并完成实验**（README 任务 C1 / C2）。设计细节、伪代码与证明见 [`Docs/basic/algorithm-design.md`](basic/algorithm-design.md)，代码 `src/basic/algorithms/prior_astar.py`；它与第 2 章的全部算法在**同一次实验**中运行，结果见 `results/basic/main/`（消融图 `figures/ablation_prior_astar.png`）。
>
> **与已有工作的关系**：乐观假设与按需重规划来自重复 A*；柱子规则来自比赛规程（除目标区外没有 2×2 空地）；对不确定的边加代价是风险规避规划的常见思路。本组的工作是把它们放进同一个可消融的框架，并提出按在线估计的墙密度自适应调整惩罚。在完成文献核查前称为“本组提出的变体”，不宣称首创。

### 4.1 设计动机，以及在基础规则下先排除的方案

第 2 章中，乐观规划（重复 A*、Flood-Fill）最好，但仍会被“看起来能走、其实有墙”的未知边误导，在部分地图上要走最短路的数倍。新方案要回答的是：**在单位步长代价下，能不能少被未知边误导？**

先排除三个候选，它们在基础规则下可以证明**不会改变重复 A* 的任何决策**：

- **转弯代价 λ 与 ε 提前停止**：基础规则下转弯不计代价、没有冲刺阶段，方案退化为重复 A*；它们留给扩展规则（见 4.6）。
- **已知死胡同剪枝**：非目标的死胡同只有一个出口，简单路径进去就出不来，不可能出现在最短路线上，A* 本来就不会规划进去；剪枝只省计算、不省步数。
- **目标区“只有一个入口”**：观测是整格四面墙，看到入口开着时，小车已经站在入口外，下一步本来就会进去。

### 4.2 方案组成

在重复 A* 上加两个可分别开关的机制：

1. **柱子规则推断墙（结构先验）**：一根内部柱子（目标区中心除外）的 4 条边中，若 3 条已确认无墙、第 4 条未知，就推断第 4 条是墙（软墙），只用于规划。观测到违反规则（某柱子四边都无墙）时，本次运行自动关闭该机制。**软墙不会让地图断开**：它的两端已由 3 条观测到的通路相连，所以推断错误不会导致失败。
2. **自适应未知边惩罚**：已确认通路代价为 1，未知边代价为 1 + δ，δ = c · p / (1 − p)。其中 p 是已观测内部边中墙的比例（Beta(1, 1) 平滑），即“未知边是墙”的几率，墙越密越偏向已确认的路。所有边代价 ≥ 1，曼哈顿启发式仍可采纳。

两个机制都关闭时，每张地图上的路线与重复 A* 逐格相同（有测试验证），因此消融结果中的差异完全来自新增机制。完备性与重复 A* 相同，每步额外开销为 O(1)。

### 4.3 实验设置

- **开发集**：种子 101～110 生成的 120 张地图，与测试集不重叠。唯一参数 c 在其上按“步数 / 最短路”均值选取，结果为 c = 2.5（固定 δ 的消融变体也取 2.5），随后冻结（`results/basic/dev/tuning.md`）。
- **测试集**：与第 2 章是同一次运行（514 张地图，每个组合 3 次），因此表 3 与表 1、表 2 的计时口径完全一致。
- **消融**：只加柱子规则、只加自适应惩罚、柱子规则 + 固定 δ、完整版；基线为重复 A*。

### 4.5 分析

**新方案没有达到设计目标。** 在全部 514 张地图上，完整版的均值 2.318、中位数 2.019，都比重复 A*（2.172、1.714）差。我们如实报告这个负面结果，并分析原因：

- **结构先验在理想观测下几乎无用。** 柱子规则在 394 张外部迷宫库地图上只改变了 3 张的路线。原因是：能推断出第 4 面墙时，小车必然已经到过这根柱子旁的两格，从那里绕行与直走步数相同，推断出的信息总是来得太晚。这与 4.1 节排除的几个先验是同一个道理：**观测越完整，先验能补充的信息越少**；在有限视野或有噪声的传感器下（3.4 节），结构先验可能更有价值。
- **未知边惩罚是“用典型情况换最坏情况”。** 在外部迷宫库上，它把最大比值从 28.1 降到 19.4（`external_sunkai` 从 28.1 降到 7.0），但 261 张地图多走路、只有 69 张少走，重复访问从 19.5 次升到 34.0 次。在生成图上，它能推广到测试集（无环图均值从 2.85 降到 2.56）。这与第 2 章发现 6 一致：**迷宫的来源决定了哪种启发式有效**。
- **自适应没有带来额外收益。** 两类地图的墙密度相近（内部边中墙的比例 0.42 对 0.47），学到的 δ 也相近（2.38 对 2.26），因此自适应 δ 与固定 δ 几乎相同。只看墙密度区分不出两类迷宫在结构上的差别。
- **方法上的教训：分布偏移。** 开发集只有生成图，参数在一种分布上选定，在另一种分布上失效。开发集应按地图来源分层，例如留出一部分外部迷宫库地图。按实验计划，看过测试结果后不再修改参数，因此下面的检验只作为事后分析。

**事后分析：按地图来源分层的开发集**（看过测试结果之后做的，**不是正式结论**；脚本与完整结果见 `src/basic/posthoc_stratified.py`、`posthoc.md`）。外部迷宫库按固定种子抽出 20%（79 张）加入开发集，与 120 张生成图一起重新选 c，选取标准与正式流程相同；再在其余 315 张外部图 + 120 张生成测试图上评估。

| 重复 A* | 2.203（1.714） | 2.211（1.815） | 2.181（1.517） | — |

分层开发集选出了 **c = 0**，即关掉未知边惩罚，方案退化为“重复 A* + 柱子规则”，在留出集上与重复 A* 几乎相同。也就是说，开发集若一开始就覆盖外部迷宫库，调参会主动放弃这个在比赛风格地图上有害的机制，不会出现正式结果中的失效。需要注意两点：这些外部图此前都作为测试集用过，留出集并非从未见过的数据；而且即使分层，新方案也只是“不变差”，没有变得更好。

对 2.6 节算法选择结论的影响：**结论不变，基础规则下仍推荐重复 A***。只有在“最坏情况比平均情况更重要”的场景（例如必须控制最长探索时间），未知边惩罚才值得考虑。

### 4.6 扩展规则下的延伸

先验增强重复 A*（完整版，c = 2.5）作为基础算法参加了 X1。五档规则下，它的平均代价比都高于重复 A*（λ = 2 时 2.769 对 2.586，表 4），与 4.5 节一致：未知边惩罚在测试集中占多数的外部迷宫库上有害，加入转弯代价没有改变这一点。

4.1 节留给扩展规则的两个思路都已在第 3 章检验：把转弯代价纳入规划（朝向 A*）没有显著收益（发现 7）；ε 提前停止满足误差界，但成绩的收益来自 ε = 0 的追加探索本身，在当前计分下 ε > 0 没有额外的平均收益，探索折算更重时才更好（发现 12）。把柱子先验、未知边惩罚与朝向 A* 结合的方案没有实现：它的两个组成部分各自都没有带来收益，本文不再推进。结构先验更可能在有噪声或有限视野的观测下发挥作用，这留作后续工作。

## 5. 局限与后续工作

- 第 2、4 章的结论建立在理想观测、单位代价和 16×16 地图上，地图来源与统计方式的局限见 2.7 节。第 3 章放宽了代价、观测与比赛流程，但运动模型与传感器参数都是未经实测校准的仿真假设，扩展实验的其他局限见 3.10 节。
- 加权 A* 的代价界只适用于单次搜索，整局代价只有实验证据。有界提前停止的 1 + ε 界在每张地图上都成立；ε 的最佳取值取决于计分中探索的折算系数，事后验证只在 X3 的数据上重算，没有覆盖其他地图或规则。
- 第 4 章新方案的开发集只含生成图，参数在外部迷宫库上失效（分布偏移）；结构先验只在理想观测下评估过。
- 后续工作：
  - 校准运动与传感器参数，引入时间或空间相关的噪声；
  - 在有噪声或有限视野的观测下重新评估结构先验；
  - 把置信度重规划的兜底规划改为按置信度加代价，而不是二值地当墙或不当墙（发现 11）；
  - 在更大的地图上检验 D* Lite 的增量优势；
  - 按计分方式在线选择 ε（事后验证已给出各折算系数下的盈亏点）；
  - 补充房间型等其他结构的地图；
  - 用元启发式为评分权重调参（3.2 节，未实现）。
