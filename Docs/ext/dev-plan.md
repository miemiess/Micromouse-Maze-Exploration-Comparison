# 扩展阶段开发计划（ext）

> 状态：**规划完成，待开发**。基础规则阶段已完成并冻结（标签 `basic-rules-v1`，代码 `src/basic/`，结果 `results/basic/`）。
> 本文是扩展阶段的唯一路线图：做什么、按什么顺序、放在哪里、怎样算完成。任务认领见根目录 README 的任务表。

## 1. 目标

在基础规则（每步代价 1、理想观测、单次到达）之上**逐项放宽假设**，回答：规则更接近真实电脑鼠比赛后，基础阶段的结论（乐观重规划最好、重复 A* 计算量最小）是否仍然成立？并借此补齐课程 Brief 中“设计启发式或近似算法”的要求。

本项目有意只建模**决策层**，以便把差异归因于策略本身；扩展阶段以可选包装层的方式加入另外两层：

| 层 | 真实电脑鼠 | 基础规则 | 扩展 |
| --- | --- | --- | --- |
| 决策层 | 选择下一步往哪走 | `src/basic/algorithms/` | 新算法：`src/ext/algorithms/` |
| 感知层 | 红外传感器融合判断有无墙 | 理想观测，四向 100% 准确 | E2：传感器噪声 + 置信度融合 |
| 控制层 | 电机加减速、转弯 | 走一格 = 1 步，转 90° 计数 | E1：运动时间模型 / 转弯代价 |

**不做**（写入报告的局限分析）：定位误差（SLAM，超出课程范围）、电机 PID（偏离主题）、强化学习（需在同一张地图上反复训练，等于泄露地图信息）。

## 2. 规则层设计

规则拆成三个相互独立的维度，可以组合：

| 维度 | 基础规则（默认） | 扩展选项 | 任务 |
| --- | --- | --- | --- |
| 代价模型 | 每步 1，转弯只计数 | 转弯代价 λ；运动时间模型（直线梯形加减速 + 转弯耗时，参数参考真实电脑鼠并记录来源） | E1 |
| 比赛流程 | 单次到达目标 | 两阶段：先探索、再从起点冲刺；ε 提前停止 | D5 |
| 观测模型 | 理想观测 | 按方向设定准确率；每面墙维护对数几率 S，w = ln(p/(1−p))，P(有墙) = 1/(1+e^(−S)) | E2 |

```python
@dataclass(frozen=True)
class Ruleset:                       # src/ext/rules/__init__.py（或经评审后放入 src/core/）
    key: str                         # "basic"、"turn_cost"、"two_phase"、"noisy" ……
    title: str                       # 界面显示名，如 "转弯代价（λ = 0.5）"
    params: dict                     # λ、ε、传感器准确率……
    def make_env(self, maze, max_steps): ...   # 基础规则返回 MazeEnvironment；噪声规则返回包装环境
    def extra_metrics(self, run) -> dict: ...  # 加权代价、预计用时、冲刺步数……
```

**接入公共接口的约定**（保证基础规则不受影响）：

- `Runner(maze, algorithm, rule=BASIC)`、`run_episode(..., rule=BASIC)`：新增可选参数，**默认值等于基础规则**，不传时行为与 `basic-rules-v1` 完全相同。
- Strategy 接口不变；需要规则参数的算法可选实现 `configure(rule)`，Runner 在 `reset` 前调用。
- 算法可声明 `supported_rules`；未声明时默认支持所有**不改变观测**的规则（基础算法在转弯代价规则下照常运行，作为“不懂规则”的对照）。改变观测的规则（噪声）只对声明支持的算法开放。
- 噪声规则会改变“撞墙 = invalid_action”的公共规则（应改为“撞墙 = 一次准确观测、原地不动”），**必须先开 Issue 达成一致**，并同步修改 `src/README.md`。
- 每次修改 `src/core/` 后运行 `tests/test_basic/test_regression.py`。

## 3. 上位机：规则切换必须一眼可见

仍用同一个上位机（`tools/MazesTest`）。主工具栏地图下拉框旁增加全局的 **“规则：[基础规则 ▼]”** 下拉框，作用于全部功能页（新文件 `tools/MazesTest/app/rule_bar.py`）。

| 位置 | 基础规则 | 扩展规则 |
| --- | --- | --- |
| 规则横幅（工具栏下方整条） | 不显示，界面与现在相同 | 醒目色条：“扩展规则：转弯代价 λ = 0.5 — 结果不可与基础规则直接比较”，参数可在横幅内调整 |
| 主题强调色 | 现有配色 | 每个规则一个固定颜色（标签页、按钮） |
| 窗口标题、状态栏 | 不变 | 末尾加“【转弯代价 λ=0.5】” |
| 算法列表 | 全部算法 | 不支持当前规则的置灰并提示原因；扩展算法带 `[EXT]` 标记（已实现） |
| 统计面板 | 步数、转向… | 增加该规则的指标：加权代价、预计用时、探索 / 冲刺步数 |
| 画布 | 不变 | 规则相关可视化：转弯点、冲刺路线、墙壁置信度着色 |
| 导出图片 / 批量实验 | 不变 | 标题带规则标签；metadata 记录规则与参数 |

切换规则时重置正在进行的运行（有未完成运行时先确认）。

## 4. 阶段与任务

| 阶段 | 任务 | 内容 | 产出位置 | 完成标准 |
| --- | --- | --- | --- | --- |
| **0. 基础设施** | E0 | `Ruleset` 与 basic 规则；`Runner` / `run_episode` / 实验框架的 `rule` 参数；`--rule` 命令行；上位机规则栏（先有 basic + 一个占位规则） | `src/ext/rules/`、`src/core/`（向后兼容）、`tools/MazesTest/app/rule_bar.py` | 回归测试通过；上位机可切换并显示横幅；metadata 记录规则 |
| **1. 转弯代价与启发式搜索** | E1、E3 | 运动时间模型与转弯代价规则；（格子, 朝向）状态上的 A*（不高估的“曼哈顿 + 转弯下界”启发式）；加权 A*（f = g + w·h，路径 ≤ w 倍最优）；可选 D* Lite（增量重算，对比计算量） | `src/ext/rules/motion.py`、`src/ext/algorithms/` | 实验计划先写好；λ / w 只在分层开发集上调；基础算法与懂规则的算法同表比较 |
| **2. 两阶段与近似算法** | D5 | 探索 + 冲刺；停止判据：乐观代价 O 与悲观代价 P 满足 P ≤ (1 + ε)·O 时停止，冲刺代价 ≤ (1 + ε)·最短路（ε = 0 时即证明最优后停止） | `src/ext/rules/two_phase.py`、`src/ext/algorithms/` | 判据可证明；“探索 + 冲刺总代价”随 ε 的曲线 |
| **3. 噪声观测（可选）** | E2 | 先开 Issue 讨论撞墙规则；噪声包装 + 对数几率融合 | `src/ext/rules/noisy_sensor.py` | 多种子重复，报告均值与离散程度 |
| **可选研究** | D4 | 迷宫难度刻画（环路比例、死胡同比例、分岔数、“欺骗度”）；用模拟退火对抗式生成最坏迷宫 | `src/ext/`、`results/ext/` | 特征与算法表现的关系分析 |
| **收尾** | 全员 | 报告第 3 章填入扩展结果；英文定稿；参考文献核查；贡献记录；在干净提交上重跑全部实验 | `Docs/Result.md` | 课程交付项全部覆盖 |

**候选算法**（来自组内讨论，按阶段认领）：

| 算法 | 要回答的问题 | 阶段 |
| --- | --- | --- |
| 转弯加权 A* / Flood-Fill | 状态扩展为（格子, 朝向），代价 = 步数 + λ×转弯；改变 λ 画出步数与转弯的权衡曲线 | 1 |
| 加权 A* | 用 w 换计算量，路径长度有 w 倍上界 | 1 |
| 增量重算（D* Lite） | 与全量重算相比路线相同、计算量不同：区分移动成本与计算成本 | 1（可选） |
| 前沿探索 | 目标从“到达终点”变为“摸清地图”，在两阶段规则下更有意义 | 2 |
| 加权评分 + 元启发式调参 | 评分 = w₁·目标距离 + w₂·转弯 + w₃·重复访问 − w₄·信息收益；“权重 → 平均步数”不可微，用随机搜索 / 模拟退火在开发集上调参 | 1 或 2 |

**建议主线：“乐观假设的代价”**——乐观规划什么时候会被误导（难度刻画、对抗迷宫）？换成转弯代价、两阶段规则后，结论是否仍然成立？用一条主线串起算法与实验，避免罗列结果。

## 5. 实验约定（沿用基础阶段的做法，并吸取其教训）

- **先写计划再运行**：每个扩展实验在 `Docs/ext/` 写实验计划（问题、地图、算法、参数候选、选取标准、指标），运行后不按结果改规则；改了要写变更记录并重跑。
- **开发集按地图来源分层**（基础阶段的教训，见报告 4.5）：划分写死在 `mazes/splits/ext_dev.json`（固定种子），同时包含生成图与一部分外部迷宫库地图；这部分外部图不进扩展测试集。
- **同一次运行、同一计时口径**：新方案与对照算法在同一个实验中运行；消融变体用类属性 `ablation_of` 声明，自动只进消融图。
- **结果目录**：`results/ext/<规则或实验名>/`，由 `src/ext/plan.py` 的 `PLANS` 注册，命令 `python src/run_experiments.py --plan <名称>`。
- **有随机性的设置**（噪声）：多种子重复，报告均值与离散程度。

## 6. 与现实的对应（用于报告的问题定义与局限分析）

扫地机器人首次进入新户型（覆盖与重复访问）、仓库机器人或无人机遇到新障碍后改道（重新规划）、搜救机器人在未知废墟中寻找目标、火星车移动代价远高于计算代价、电脑鼠比赛（两阶段规则）。仿真与现实的主要差距：理想观测、统一步长代价、四向观测、已知自身位置、不限电量。扩展阶段放宽其中的代价与观测两项，其余写入局限分析。

上述 D* Lite、两阶段规则、加权 A* 等均为已有方法；本组的贡献在于放进统一框架比较与分析，完成文献核查前不宣称首创。
